# MMD 动作使用说明

## 添加动作

1. 打开 `BepInEx/plugins/Seleka2VmdProbe/Motions`。
2. 新建一个文件夹，文件夹名字就是游戏里显示的动作名称。
3. 把动作文件放进去，按照下表命名。
4. 重启游戏，在环状列表中选择该动作。

| 文件名 | 用途 | 是否必需 |
| --- | --- | --- |
| `motion.vmd` | 角色动作 | 必需 |
| `camera.vmd` | 配套镜头 | 可选 |
| `BGM.wav` | 配套音乐 | 可选 |
| `source.pmd` | 动作配套的 MMD 模型，用于帮助匹配动作 | 可选 |
| `action.json` | 自定义名称、文件名或播放参数 | 可选 |

例如：

```text
Motions/
  我的舞蹈/
    motion.vmd
    camera.vmd
    BGM.wav
    source.pmd
```

**只放 motion.vmd 就能播放，不需要 JSON。** 没有音乐就静音，没有配套镜头就使用游戏镜头，没有配套模型时，从游戏角色的网格绑定姿势生成虚拟 MMD 骨架。source.pmd 不会替换玩家外观；目前只支持 PMD，不支持 PMX。

动作和音乐在后台准备，不需要等全部动作加载完成才进入游戏。动作解析完成后会逐步加入列表；已打开的转盘重新打开后可看到新增动作。选择的动作尚未准备好时会稍后开始，按取消可以撤销等待；不会自动播放未选择的动作。

音乐请使用 WAV，支持单/双声道 PCM16 或 float32。不同动作请使用不同的文件夹名字；名字不要包含英文逗号。

## 播放和设置

在环状列表中选择动作开始播放。移动、取消或再次选择相同动作可以停止；打开其他界面也会中止动作。请站立并停止移动，手铐等游戏状态可能限制动作。

在 **设置 → 游戏系统** 下方调整动作音乐音量、面部镜头跟随和 MMD 配套镜头开关。安装 NPC 围观插件后，开启“MMD动作触发”和“所有MMD动作”，可让普通行人靠近围观。

## 什么时候需要 JSON

使用上面的默认文件名时，通常不需要 JSON。需要调整时，在动作文件夹里新建 `action.json`，只写需要改变的内容，其余保持默认。

可以用记事本编辑。确认文件名是 `action.json`，不是 `action.json.txt`。下面的示例可以直接复制；JSON 中不能添加注释。

### 音乐晚 1 秒开始

```json
{
  "audioDelaySeconds": 1
}
```

### 单独降低这个动作的音乐音量

```json
{
  "volume": 0.7
}
```

默认是 1，0 为静音；同时受设置页的动作音乐音量影响。

### 不想重命名下载的文件

```json
{
  "vmdFile": "动作＋表情.vmd",
  "audioFile": "音乐.wav",
  "modelFile": "配套模型.pmd",
  "camera": {
    "vmdFile": "镜头.vmd"
  }
}
```

文件放在 action.json 旁边。没有音乐、模型或镜头，就不要填写对应项。

### 改显示名称，同时微调镜头高度

```json
{
  "displayName": "我的舞蹈特别版",
  "camera": {
    "heightOffset": 0.1
  }
}
```

镜头仍会自动使用 camera.vmd。高度偏移默认是 0，正数抬高、负数降低。

### 文件存在，但不使用音乐和配套镜头

```json
{
  "audioFile": "",
  "camera": {
    "enabled": false
  }
}
```

不同示例可以合并到同一个 JSON 中。每个动作只放一份 action.json，修改后重启游戏。

## JSON 参数一览

下面列出全部动作配置参数。**所有参数都可以省略，只填写需要改变的项。** 文件名和文字用英文双引号包围，数字不加引号，开关填写 `true`（开启）或 `false`（关闭）。不要填写 `null`；参数名拼错会在 BepInEx 日志中提示。

### 名称和文件

| 参数 | 默认值 | 用途与示例 |
| --- | --- | --- |
| `id` | 文件夹名 | 动作的固定标识，不能与其他动作重复或包含英文逗号。例如 `"id": "mydance"`。通常不需要填写；修改它不会改变默认显示名称。改文件夹名会改变默认标识，需要固定时再填写此项。 |
| `displayName` | 文件夹名 | 环状列表显示的名称，例如 `"displayName": "我的舞蹈"`。 |
| `description` | 空 | 动作备注文字，不影响播放；目前不会在游戏中显示说明。 |
| `vmdFile` | `motion.vmd` | 动作文件，例如 `"vmdFile": "动作.vmd"`。此文件必须存在。 |
| `audioFile` | 存在时使用 `BGM.wav` | 音乐文件，例如 `"audioFile": "音乐.wav"`。填写空字符串 `""` 可禁用音乐；省略则自动查找默认文件。 |
| `modelFile` | 存在时使用 `source.pmd`，否则从游戏绑定姿势生成虚拟 MMD 骨架 | 配套 PMD 模型文件，例如 `"modelFile": "配套模型.pmd"`。只帮助匹配动作，不替换玩家外观。 |
| `referencePose` | `"A"` | 游戏生成骨架的参考姿势；`"A"` 采用约 30° 上臂下垂校准，`"T"` 沿用原游戏绑定参考。字段和值不区分大小写，只接受 A/T 字符串。有配套 PMD 时仍使用 PMD 自身参考姿势，不再叠加此校准。 |

所有资源路径相对于 action.json 所在文件夹，可以写 `"音乐/BGM.wav"` 这样的子文件夹路径。不要填写电脑上的绝对地址，也不要指向动作文件夹以外。

### 播放、音量和动作范围

| 参数 | 默认值 | 用途与填写条件 |
| --- | --- | --- |
| `audioDelaySeconds` | `0` | 音乐比动作晚多少秒开始。只能填写大于或等于 0 的数字，例如 `1.5`。 |
| `volume` | `1` | 这个动作的音乐音量倍率，范围 `0`～`1`。还会受到设置页音量影响。 |
| `loop` | `false` | 是否循环角色动作。当前只支持静音动作循环；使用 `true` 时需要关闭音乐。 |
| `requiresHands` | `true` | 是否要求双手可用。手铐等状态会限制需要双手的动作。只有 `bodyMask` 为 `"LowerBody"` 且 `writeFaceMorphs` 为 `false` 时，才可填写 `false`；其他游戏限制仍然生效。 |
| `requiresStanding` | `true` | 是否要求角色站立。填写 `false` 只取消这项要求，其他游戏状态仍可能限制播放。 |
| `bodyMask` | `"FullBody"` | 动作控制范围：`"FullBody"` 为全身；`"UpperBody"` 为上半身，不包括髋部；`"LowerBody"` 只控制腿部。 |
| `writeHipTranslation` | `true` | 是否使用动作位移：水平走位交给原角色控制器，上下起伏应用于髋部。只有动作范围包含髋部时有效；false 关闭两者。 |
| `keepGameExpressions` | `true` | 是否保留原游戏表情叠加；false 优先于游戏内开关。 |
| `writeFaceMorphs` | `true` | 是否使用 VMD 中已支持的表情，如眨眼和嘴型。并非所有 MMD 表情都有对应效果。 |
| `followFaceCamera` | `true` | 是否让游戏原有的面部摄像机跟随这个动作。仍受设置页开关控制，与配套主镜头的开关分开。 |
| `showInRing` | `true` | 是否出现在环状列表。设为 `false` 后无法从列表选中，通常保持默认即可。 |
| `bonePaths` | `[]` | 高级选项：仅使用指定骨骼的动作。留空表示使用 bodyMask 范围内的全部骨骼。填写的是游戏骨骼完整路径，不是 MMD 的骨骼名；路径必须位于所选动作范围内，且不能重复。 |

只循环腿部动作、不使用音乐和表情的例子：

```json
{
  "audioFile": "",
  "loop": true,
  "bodyMask": "LowerBody",
  "requiresHands": false,
  "writeFaceMorphs": false
}
```

只使用头部骨骼动作的高级例子：

```json
{
  "bodyMask": "UpperBody",
  "writeFaceMorphs": false,
  "bonePaths": [
    "Armature/Hips/Spine/Chest/Neck/Head"
  ]
}
```

### 镜头参数

镜头参数放在 `"camera": { ... }` 里面，不要直接写到最外层。只填写其中一项时，其余镜头参数仍保持默认。

| 参数 | 默认值 | 用途与示例 |
| --- | --- | --- |
| `camera.vmdFile` | 存在时使用 `camera.vmd` | 配套镜头文件，例如 `"vmdFile": "镜头.vmd"`。没有默认文件时跳过配套镜头。 |
| `camera.enabled` | `true` | 是否使用这个动作的配套镜头。设置页的 MMD 镜头总开关也需要开启。 |
| `camera.timeOffsetSeconds` | `0` | 镜头相对于动作的时间偏移。正数让镜头晚开始，负数从镜头较后的位置开始；与音乐延迟独立。 |
| `camera.scale` | `0.08` | 镜头位置和距离的比例。调整不合适的镜头取景时使用，通常保持默认。必须大于 0，最大为 100。 |
| `camera.heightOffset` | `0` | 整体镜头高度偏移，单位为游戏中的米。正数抬高、负数降低，例如 `0.1`。 |

0.7.3 起镜头默认按每 MMD 单位 0.08 个游戏单位换算，位置和距离一起缩放。镜头转换不读取模型身高、腿长或配套 PMD；modelFile 只参与动作骨架/IK 重定向。已显式填写的 camera.scale 优先，默认不额外添加高度偏移。

例如，镜头晚半秒开始并抬高一点：

```json
{
  "camera": {
    "timeOffsetSeconds": 0.5,
    "heightOffset": 0.1
  }
}
```

这里的 `camera.vmdFile` 只是表格中的写法；实际 JSON 应按上面的示例放入 camera 对象。不要填写 schemaVersion、bundle、clipAsset、audioAsset 或 showInTab，它们不属于此插件的动作参数。

## 动作事件

可以在指定时间播放原版音效、脚步或召集 NPC 围观。与音乐延迟、镜头参数一样，事件也是可选配置，不填写就保持原来的播放方式。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `events` | `[]` | 指定时间点执行的事件。每条填写 time、event，可选 args、repeat。 |
| `onStart` | `[]` | 动作实际开始时执行。每条填写 event，可选 args。 |
| `onFinish` | `[]` | 动作和音乐全部正常结束时执行。 |
| `onCancel` | `[]` | 已开始的动作中断时执行。临时请求仍会自动清理。 |
| `useClipEvents` | `true` | 仅用于 Unity 动画包的内置事件，对 VMD 无影响。 |

例如，仅让这个动作触发围观：

```json
{
  "onStart": [
    { "event": "npc.spectators" }
  ]
}
```

需要安装 NPC 围观插件并开启其总开关；动作停止会自动释放这次请求。完整事件参数、音效与脚步示例见旁边的 [动作事件说明.zh-CN.md](../shared/动作事件说明.zh-CN.md)。

## 现有动作举例

**Shake** 使用默认文件名，可以不带 JSON。

**WAVEFILE** 会自动使用旁边的 source.pmd，只需要设置音乐延迟：

```json
{
  "audioDelaySeconds": 5.333333333333333
}
```

## 常见问题

- **列表里没有动作：** 检查 motion.vmd 的名字、所在文件夹和 JSON 格式，修改后重启游戏。
- **写了文件名却没有加载：** 检查指定文件是否存在。主动填写的文件名不会自动换回默认文件；vmdFile 和 modelFile 不能留空。
- **没有音乐：** 检查 BGM.wav；如果 JSON 指定了 audioFile，就检查指定的文件。
- **没有配套镜头：** 检查 camera.vmd，并开启设置页的 MMD 配套镜头。
- **动作姿势不对：** 有原动作配套的 PMD 模型时，可放入并命名为 source.pmd。部分动作的脚部、表情或特殊骨骼仍可能存在偏差。

0.8.0 起默认保留动作走位，使用游戏现有碰撞控制器；受阻或取消时停止并保留已到达位置。镜头沿原始轨迹播放，不增加根位移补偿。开源出处与许可见 THIRD_PARTY_NOTICES.md。

## 原游戏表情叠加（更多动作 0.5.0 / MMD 0.9.0）

游戏设置新增 `[更多动作] 叠加原游戏表情`，默认开启。打开游戏设置会按原规则中止当前动作，修改后下次播放生效。开启时在原游戏表情上叠加动作表情，同通道权重相加并限制在 0–100（动作当前支持眨眼与五个元音口型）；关闭时仅显示动作表情，未映射到动作的动态表情通道归零。捏脸形状保留，停止/取消后归还原游戏表情，不修改游戏存档。

每个动作 JSON 可设置 `"keepGameExpressions": false` 强制关闭叠加，此时游戏设置开启也无效。省略或为 true 时由游戏设置决定。例如：

```json
{ "keepGameExpressions": false }
```

`writeFaceMorphs: false` 仍表示动作完全不接管表情，此时两种叠加设置均不影响原游戏表情。界面开关保存于更多动作插件配置的 `[Face] KeepGameExpressions`，不重写动作 JSON。JSON 在下次启动导入动作时读取。

## 身体姿势接管（更多动作 0.5.1 / MMD 0.9.1）

MMD 播放时接管动作范围内的身体骨骼位置、旋转和体型缩放基准。原版膝盖、脚趾及视线控制仍更新内部状态，但对已接管骨骼的动态写入被隔离；体型、骨长和鞋跟计算保持。每帧进入原生更新前撤回上一帧姿势，避免局部位置累积；结束、取消和场景销毁时恢复原生姿势及 Animator 的原裁剪模式。头发、裙摆等物理链不接管，移动碰撞和取消规则不变。无需增加 JSON 字段。

## 深屈膝 IK 限制（MMD 0.9.3）

修复游戏生成骨架在深屈膝时进入超过 180 度的反折分支。膝盖限制使用带符号的铰链投影，并考虑绑定姿势已有的弯曲角度；同一旋转的 q 与 -q 保持一致。没有改变移动碰撞、镜头或体型。显式配套 PMD 暂保留原求解路径。

## 骨骼插值布局（MMD 0.9.4）

骨骼贝塞尔控制点对齐 UnityVMDPlayer 的 UnityVMDReader：分别从 64 字节的 0/16/32/48 通道段读取，每段使用 0/4/8/12 偏移。保留现有贝塞尔求值精度、Slerp、时间与边界策略。本次不改骨架生成和 IK，不代表已解决全部跪姿适配问题。

## 生成骨架的世界尺度（MMD 0.9.6）

游戏生成的虚拟 MMD 骨架现在包含模型根及祖先的有效缩放，腿部求解和根位移换算使用同一套世界尺度，避免默认模型的固有缩放被遗漏。缓存形状包括该尺度；同体型读档、世界位置和朝向变化仍重绑定复用。没有增加骨盆高度或镜头补偿，也未改碰撞与取消。显式配套 PMD 暂保留原重定向尺度行为；运行时腿长比例自定义的完整中立校准仍不由本项缩放修复自动保证。

## 日志整理（更多动作 0.5.3 / MMD 0.9.7）

移除本轮定位使用的定点骨骼采样、空间快照及其专用播放监听。保留正常启动、资源准备、动作开始/停止与异常日志。已在原游戏确认 Samsa 25–26 秒段的世界尺度修正生效；这不表示所有动作、体型及接地情况均已完整验证。


## 默认 A-pose 校准（MMD 0.9.9）

参考 UnityVMDPlayer 的 `EnforceInitialPose`，游戏生成的虚拟骨架默认将左右上臂镜像下垂约 30°，前臂、手腕及手指随之调整参考方向，再计算映射回游戏骨架的旋转校准。保留实际骨长、体型、世界尺度及原游戏绑定数据。这个通用预设不等于每份动作原模型的精确姿势，不保证所有合掌及接触片段完全一致。

无需配置即可启用默认 A-pose。逐动作切换 T-pose 时，在原 JSON 中加入 `referencePose`，例如 WAVEFILE 保留原音乐延迟：

```json
{
  "audioDelaySeconds": 5.333333333333333,
  "referencePose": "T"
}
```

改成 `"A"` 或省略该字段恢复默认；修改 JSON 后重启游戏。A/T 使用独立的预热与缓存条目，同体型读档仍可复用。配套 PMD 保持原有求解参考，不受此选项改变。日志用 `game-bind-pose:A/T` 区分实际模式。
