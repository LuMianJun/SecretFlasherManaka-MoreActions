# 异步加载与骨架复用（MMD 0.7.1 / 更多动作 0.3.2）

用户已确认游戏绑定姿势生成的虚拟 MMD 骨架效果。此批保留该姿势求解方案及配套 PMD 分支，清理已被替代的旧默认 PMD 扩展路径，并改变准备时机。

## 准备阶段

- 插件启动只发现动作目录、读取小型 JSON 并排入后台队列；不等 VMD、镜头或音乐全部加载才允许进入游戏。
- 单个 VMD 工作队列解析动作、镜头和配套 PMD 元数据。解析部分使用托管数学与数据，不调用 Unity 方法；结果回到主线程后，每帧至多注册一个动作。错误动作单独拒绝，错误镜头不影响其有效动作。
- 通用动作运行时在标题/加载期间也推进资源准备。WAV 由受限后台队列读取并转换成 PCM 浮点采样，AudioClip 创建和 SetData 留在主线程，每帧至多上传 262144 个 float（1 MiB），尾块按实际长度和声道帧偏移写入。
- 选择的动作获得资源准备优先级。尚未准备好时保留请求，等待音乐和骨架就绪；取消会清除待播放请求，后续准备完成也不会启动。准备本身不播放动作、不执行事件或写玩家姿势。
- 动作异步加入注册表后恢复配置中记住的快捷槽；不要求先打开一次转盘。已经打开的转盘在下次打开时显示新加入的项目。

## 骨架缓存

- 缓存键为玩家目标实例和源骨架模式。无配套模型的动作共用一套游戏生成骨架；同路径配套 PMD 使用其独立模板和求解骨架。
- 角色就绪、原生缩放包装节点稳定后分帧准备，每帧至多建立一种源骨架。播放入口检查准备状态，不在第一次点击时强制创建冷骨架。
- 缓存保留源/目标辅助节点、绑定姿势、骨骼映射和轴向修正。每次播放仍独立记录旋转、髋部和表情恢复值，重新指定关键帧、遮罩、写入标志和第零帧位移基准。
- 独立并发使用者得到独立可变求解器；不会共用正在求解的骨架。闲置辅助骨架复用，临时并发实例结束后销毁。
- 玩家实例更换、原生体型 ReAdjust 或引用网格变化时使相应缓存失效。已租用的旧骨架等本次恢复完成再销毁，避免提前销毁造成恢复异常。
- 配套 PMD 元数据只在后台首次读取，缓存骨架实例从模板复制。修改文件仍需重启游戏，不引入热重载。

## 清理与观察

生产代码不再包含 AddExtendedStandardBones 及旧参考 PMD 的补骨路径。安装器仅在 SHA256 匹配已知随包参考时，将旧 reference-skeleton.pmd 备份后移除；不删除未知同名文件，不动任何动作目录的 source.pmd。历史代码/资源备份保留作回滚及测试对照。

日志可区分后台总准备时长、主线程音频单步上传时长、骨架预热时长和每次播放姿势创建时长：`MMD_VMD_READY parseMs`、`ACTION_ASSETS_READY prepareMs/uploadStepMaxMs`、`MMD_RIG_READY prepareMs`、`ACTION_START poseMs`。后台总耗时包含排队，不能当作一帧卡顿时间。

离线验证覆盖精确音频采样、线程边界、缓存复用、每次恢复、并发隔离、准备中取消、异步注册和错误隔离。Unity 对象分配及 API 调用仍需主线程；实际帧时间和进入游戏耗时须以原游戏测试为准，不由离线断言推算。
