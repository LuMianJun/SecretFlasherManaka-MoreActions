# 异步加载与骨架复用（MMD 0.10.0）

## 后台与主线程边界

- 动作目录发现后，将 VMD 和镜头 VMD 解析交给受限后台队列；主线程每帧最多登记一个完成的动作，坏包单独隔离。
- WAV 的解析/解码由更多动作后台处理，Unity AudioClip 创建及数据上传仍在主线程分步执行。
- 骨架准备先分帧捕获游戏骨骼引用、绑定姿势和形状签名，再在后台按实际世界尺寸生成 A/T 参考几何，最后按帧创建 Unity 辅助节点。
- PMD 解析与模型模板缓存已移除，没有额外模型读取任务。

## 缓存与恢复

- 缓存按角色实例与 A/T 参考模式区分，持久保有虚拟控制骨架和目标采样代理；每次播放只创建独立姿势租约与恢复快照。
- 相同体型读档优先重绑定保留的辅助骨架。ReAdjust 只触发形状核验，不等同于强制重建；有效尺度或网格绑定形状变化才建立对应新实例。
- 每种模式保留有限的旧形状实例；并发租用同一角色时创建独立求解器。已租用实例在归还前不会提前销毁。
- 源码、JSON 及动作文件修改后需重启游戏，不提供热重载。

## 日志与边界

保留 `MMD_VMD_READY parseMs`、`ACTION_ASSETS_READY prepareMs/uploadStepMaxMs`、`MMD_RIG_READY totalMs/maxOperationMs`、`ACTION_START poseMs` 及异常日志；`game-bind-pose:A/T` 表明实际参考模式。后台总耗时包含排队，不等于单帧阻塞。

本轮手部定点采样已清理。离线验证覆盖线程边界、精确音频、缓存复用、每次恢复、并发隔离、分帧冷构建、异步注册和错误隔离。实际帧时间及进入游戏耗时仍以原游戏测试为准。
