# UnityVMDPlayer 功能对照

对照版本：[hobosore/UnityVMDPlayer `2cee8abd56c68ad3e88bcf4086e33185aa5ca4e8`](https://github.com/hobosore/UnityVMDPlayer/tree/2cee8abd56c68ad3e88bcf4086e33185aa5ca4e8)。此表比较实际读取器与播放器实现，不把枚举、字段存在直接视为已经完整支持。

## 表情：已扩展并改用固定基础模型

上游 MorphPlayer 遍历子层级的 SkinnedMeshRenderer，按同名或唯一包含的 VMD Morph 名绑定并采样权重。本地此前仅绑定眨眼和五个元音；0.11.0 扩展后，0.11.1 按单一基础模型约束移除通用扫描，内置 `Body.001` 的 48 个标准 MMD 表情名称/索引和原生动态表情索引。

- 直接定位固定网格，不搜索衣服、物理骨骼或其他模型；首次只验证声明的形变槽位，随后复用。
- 按固定表的原名匹配 VMD，兼容唯一的全/半角规范化名称；不猜测子串、数字前缀或自定义表情语义。
- 标准 MMD 通道与英文原生表情通道不重复驱动；原生通道仍承担游戏表情叠加/抑制。
- 继承 JSON 硬限制、捏脸保护、每次采样撤回和停止恢复。布局不符时只跳过表情写入并记录日志。
- 网格绑定姿势独立缓存，读档重绑引用并核对实际体型；相同网格/体型复用求解器。

`MMD_MORPHS_BOUND` 显示输入轨道数、绑定源轨道数、目标数、歧义源名称数和少量未映射名称。实机速度仍需结合预热阶段日志确认。

## 上游已有、本地尚未开放

| 能力 | 上游入口 | 当前状态与注意点 |
| --- | --- | --- |
| 手动暂停/继续 | Pause / Play | 当前源码已处理游戏暂停时的自动冻结与恢复，覆盖 DSP 音乐、事件、镜头和根位移。公共动作 API 仍只有请求/停止，没有向玩家或外部调用者开放手动暂停入口。 |
| 跳到指定帧 | JumpToFrame | 当前按统一播放时钟前进，没有跳帧 API 或进度 UI。不能只跳骨骼，必须同步音乐、镜头及事件生命周期。上游另有 Play(VMDReader,int)，但其后调用的 Play(VMDReader) 会将帧重置为零，不能据此认定“从指定帧开始”重载正常工作。 |
| 可配置时间推进速率 | SetFPS | 上游用 FPS 推进动画帧，调整也影响播放速度。本地 VMD 固定 30 帧/秒，与 DSP 时钟同步；没有播放速率接口。 |
| 左右脚独立 IK 目标偏移 | LeftFootOffset / RightFootOffset | 本地已支持脚/脚趾 IK 和世界单位校准，但没有逐脚目标偏移配置。 |
| 全亲独立启用开关 | UseParentOfAll | 本地已组合全亲/中心/槽位移；writeHipTranslation 可关闭位置写回，但不等同于独立忽略全亲轨道。 |
| 部分非髋骨的位置轨道写回 | UpperBodyAnimation / LowerBodyAnimation | 上游对部分骨骼叠加位置关键帧。本地求解器读取这些轨道，但实际角色主要接收旋转及髋/根位移；直接写其他骨局部位置可能改变游戏骨长，属于有意限制，不能照搬。此前 WAVEFILE 合掌段这些手臂位移为零，不能将此差距当作该段已证实的偏差原因。 |

## 已覆盖或属于不同架构

| 能力 | 当前情况 |
| --- | --- |
| VMD 读取、骨骼/表情采样、坐标转换 | 已有；骨骼插值布局已对齐上游读取器。本地保留自身边界策略与稀疏求解器。 |
| 循环、开始/结束通知、异步加载 | 已有对应能力。动作 onStart/onFinish/onCancel 及事件系统还承担游戏侧生命周期；异步准备与缓存也已接入。 |
| 默认 A-pose | 已参考上游约 30° 上臂下垂处理，并提供动作 JSON A/T 选择。 |
| 脚/脚趾 IK | 两者都有，但上游使用自身求解器，本地使用生成骨架 CCD 与膝盖限制。算法差异不等于缺少该功能。 |
| 手指与捩转 | 本地生成手指和虚拟捩骨。上游另声明可选上臂捩骨 Transform；额外实体骨映射与上游实际分支仍需单独核验，不据字段直接承诺可移植。 |
| 任意 Unity Humanoid 模型绑定 | 上游依赖 Animator 人形骨 API；本地面向游戏既有骨架路径与包装节点。通用 Humanoid 模型支持不属于当前插件目标。 |
| 编辑器脚偏移 Gizmo | 上游调试可视化；不是当前玩家流程的缺失功能。 |

## 不能算作“上游有、本地没有”

- 眼球骨骼：上游读取器定义了左目/右目/両目枚举，但此固定版本播放器没有实际的人形眼骨绑定，不据枚举宣称它完整支持。
- 纯表情 VMD 独立播放：此版本读取器帧数取有关键帧的骨骼组最大帧，空骨骼组路径不足以证明可直接播放纯表情文件。本地也仍需要可播放身体轨道；独立表情文件合并应作为另一个明确功能设计。
- 材质/UV Morph、MMD 刚体物理、自动合掌适配：该组件没有对应完整运行时实现，不应当作可直接搬来的现成功能。

## 建议顺序

表情映射及保护已完成本轮验证；后续可按需要开放手动暂停/继续与跳帧同步；脚目标偏移和全亲开关可另行评估。不改变已确定的“按游戏骨架生成参考姿势、保留游戏骨长”路线，也不重新引入配套模型路径。
