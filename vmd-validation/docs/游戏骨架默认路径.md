# 游戏骨架生成的默认 MMD 骨架（0.7.1）

没有配套 `source.pmd`、也未显式配置 `modelFile` 的动作，现在从玩家网格的绑定姿势生成虚拟 MMD 骨架。原有稀疏 JSON、文件夹命名、动作/音乐/镜头默认规则不变。有配套 PMD 时继续读取配套骨架，不使用生成路径。

## 数据和求解

- 读取与现有求解器相同的网格 bind poses，优先 Body.001，采用相对于玩家根节点的矩阵；不把当前待机旋转当作中立姿势。
- 49 个目标身体骨的绑定位置确定躯干、四肢和手指的位置。Toe 有绑定姿势时才生成脚趾和脚趾 IK；缺少必要身体骨、非法坐标或零长度腿时明确拒绝。
- 生成标准 MMD 控制层级：全亲、中心、槽、腰、上半身 1/2/3、肩 P/C、腕/手扭转及双脚/脚趾 IK。上半身2的位置采用 Spine 与 Chest 中点；虚拟控制层级是实现假设，不是从 VMD 恢复出的原模型信息。
- 虚拟骨架只用于求解，不添加或重排玩家实际骨骼。保留原 Animator、原体型调整包装节点、身体遮罩、表情开关、停止恢复和原生状态限制。
- 绑定位置除以既有默认换算值 `0.06630271`，在 MMD 单位中与 VMD 位移一起求解，随后按目标/源腿长比例转换回游戏单位，避免把米与 MMD 位移单位混用。
- 扭转骨沿对应肢体方向限制旋转分量；脚 IK 链使用膝盖和大腿，脚趾 IK 使用脚踝。继续尊重现有求解器中的 VMD IK 开关和有轨道才启用的规则。
- 根位移仍只应用竖直分量。参考轴来自绑定姿势，每次播放仍独立保存并恢复玩家旋转、髋部位置及已写入的表情。

## 验证与边界

`SkeletonValidation` 链接生产解析器、拓扑生成器及重定向器，使用 System.Numerics 实现离线场景/数学边界，覆盖单位、缺失/非法输入、IK 收敛、不同待机姿势、遮罩、停止恢复和本地实际 VMD。冻结的 `LegacyRuntimeVmdSource.cs` 只属于测试项目，用于比较配套 PMD 分支；不编入插件。

该验证不能代替 Unity 渲染、游戏内体型调整和视觉验收。生成骨架采用游戏绑定体型和假定的标准 MMD 层级，不保证与原动作专属模型完全一致；特殊骨骼、接触位置、膝盖/脚部偏差及非标准轨道仍可能需要后续调整。PMX 配套模型尚不支持。

0.7.0 首版的视觉效果已由用户确认。0.7.1 移除旧默认 PMD 扩展代码，动作/镜头与配套 PMD 元数据在后台解析，WAV 后台解码并按帧上传。同一角色与源骨架模式复用求解骨架，每次播放只创建独立恢复快照；角色/体型变化后重新准备。后台与缓存变更仍需游戏内性能验收。


0.8.0 更新：默认生成骨架单位现为 0.08，且启用水平根位移控制器接入；以 [根位移与角色控制器](根位移与角色控制器.md) 为准，前述首版竖直-only 描述仅保留为历史记录。
