# MMD 动作使用说明

简体中文 | [English](README.en.md)

## 快速开始

### 可以做什么

将 VMD 动作放入文件夹，即可从原版转盘播放到游戏角色上；支持配套音乐、镜头、走位和基础模型标准表情。安装 NPC 围观插件后，还可让普通行人走近围观。

先按[仓库首页](../README.md#安装)从 Release 安装“更多动作 + MMD”，再准备动作文件。

### 添加动作

1. 打开 `BepInEx/plugins/SFMVmdProbe/Motions`。
2. 新建一个文件夹，文件夹名字就是游戏里显示的动作名称。
3. 把动作文件放进去，按照下表命名。
4. 重启游戏，按下节步骤从转盘播放。

| 文件名 | 用途 | 是否必需 |
| --- | --- | --- |
| `motion.vmd` | 角色动作 | 必需 |
| `face.vmd` | 独立表情，覆盖主动作中的同名表情通道 | 可选 |
| `lip.vmd` | 独立口型，最后覆盖同名嘴部通道 | 可选 |
| `camera.vmd` | 配套镜头 | 可选 |
| `BGM.wav` 或 `BGM.mp3` | 配套音乐 | 可选 |
| `lyrics.lrc` | 随配乐显示的逐行歌词 | 可选 |

动作、表情、口型分开提供时，把表情命名为 `face.vmd`、口型命名为 `lip.vmd`，放在同一动作目录。按“主动作 → 附加表情 → 附加口型”的顺序处理，后面的文件覆盖前面同名的通道，没有涉及的通道保留。口型文件只应用嘴部表情；两个附加文件的身体、眼球骨骼和镜头数据均不应用。

表情和口型从动作第 0 秒同步播放，较短时保持最后一帧，较长时按主动作时长截断。指定的附加文件缺失、损坏或没有可用轨道时，日志记录 `MMD_FACE_REJECTED` 或 `MMD_LIP_REJECTED`，保留前一层结果，其他有效层继续使用；未指定且没有默认文件时直接跳过。原游戏表情是否叠加仍由原有设置控制。

把 UTF-8 歌词保存为 `lyrics.lrc`，放在 `motion.vmd` 所在的动作目录；也可用 `lyricsFile` 指定其他名字。时间标签如 `[00:17.90]`，表示配乐开始后 17.90 秒显示该行。歌词随配乐暂停和继续，配乐结束时清空。

例如：

```text
Motions/
  我的舞蹈/
    motion.vmd
    face.vmd
    lip.vmd
    camera.vmd
    BGM.wav
    lyrics.lrc
```

### 从转盘播放

1. 进入场景，让角色站立并停止移动。
2. 按住数字键 **1–8** 中任意一个，打开对应的原版转盘。
3. 保持按住数字键，用 **Z / X** 切页，找到导入的自定义动作。
4. 移动鼠标指向动作，松开数字键即可播放；也可以按鼠标左键确认。

以上为默认键位，改过游戏按键时以自己的绑定为准。每个转盘会记住所选动作，之后短按对应数字键即可再次执行。

资源在后台准备，动作尚未出现在列表时，稍后重新打开转盘。选中仍在加载的动作后会等待资源就绪；再次选择同一动作可撤销等待，选择其他动作则切换等待目标。

### 停止、切换与菜单

移动或再次选择同一动作可停止播放，选择其他自定义动作可切换播放。切换原版操作或进入受限状态也会停止。

从原版允许互切的姿势切换时，播放器先等资源准备好，再退出原动作并接续播放。手铐、蹲下、坐下和特殊交互等状态仍按原版规则处理。

按 Tab、Esc 打开菜单时保留当前动作。菜单使游戏暂停时，动作、音乐和镜头一起暂停，关闭后继续。

支持走位的动作经过游戏角色控制器移动，保留碰撞；受阻会停止，结束后留在实际到达的位置。头发、裙摆等物理仍由游戏处理。

腿部按角色的大腿、小腿长度求解，保留动作的下蹲、抬脚、跳跃和跪地。目标超出关节活动范围时，脚部取最近可达位置，保持腿长和动作原有髋部轨迹；不会额外把所有脚步吸附到游戏地面。

已移除大幅转腿时的额外膝盖扭转，减少脚部已经到位、膝盖却转向另一侧的异常。部分坐下或手脚触地动作仍会穿地，脚部也可能不自然翻转，详见下方常见问题。

### 游戏内设置

打开 **设置 → 更多动作**：

- **动作音乐音量：** 调整自定义动作的配乐音量。
- **叠加原游戏表情：** 默认开启，在游戏原有表情上叠加动作表情；关闭后使用动作表情。
- **面部镜头跟随：** 播放时让原版面部摄像机跟随头部，是否显示由原版设置控制。
- **使用配套镜头：** 开关动作自带的镜头。

需要围观时，安装 NPC 围观插件，打开 **设置 → 游戏系统**，开启围观总开关、“MMD动作触发”和“所有MMD动作”，然后关闭设置并播放动作。

## 高级使用

### 资源与加载说明

配乐文件命名为 BGM.wav 或 BGM.mp3，二者共存时优先使用 BGM.wav。其他文件名通过 action.json 的 audioFile 指定。

音乐支持 MP3，以及单/双声道 PCM16、float32 WAV；MP3 由游戏原生接口异步解码。每个动作使用唯一文件夹名，文件夹名需避开英文逗号。

### 骨骼与辅助轨道

支持动作文件中的眼球、脚趾、足先 EX、大腿 D／膝 D／足首 D，以及腰、肩取消旋转。角色已有的上臂和前臂扭转骨分别承接捩转；普通两关节拇指和带亲指 0 的三关节拇指均可使用。躯干层级压缩会同时传递位置变化，补偿胸口、手和头因层级差异产生的位置偏移。

Unity 动作与 MMD 使用同一份固定角色骨骼预设校验 `bonePaths`。MMD 支持的附加骨可用同名 VMD 轨道驱动，仅在有对应轨道时接管；手臂扭转骨随对应手臂接管。显式选择的路径必须位于公共预设和动作范围内，播放前还会检查目标角色实际存在该骨骼且有绑定参考数据。`BreastRotateL/R` 是原生乳部控制父级，MMD 沿用原游戏控制，不直接接管这两个节点。

骨骼路径与映射读取更多动作目录中的 `BepInEx/plugins/SFMMoreActions/body-bones.json`，首次使用后缓存在内存中，启动时主动校验。请保留安装包附带的这份公共清单，更新时与 DLL 一起替换。插件不扫描角色生成或保存清单；当前角色的身高、腿长及绑定数据仍在准备参考骨架时读取，并按目标与外观尺寸复用，这些动态数据不写入 JSON。

`MMD_BONES_BOUND` 会列出仍未匹配的有效动作轨道。模型专有的发丝、衣物或道具骨不能仅凭近似名称套到另一根骨骼上；更换基础角色模型需要相应适配。

脚部仍保留原动作的抬脚、跳跃、下蹲和髋部轨迹，不会自动贴地或避开场景墙面。

### 播放日志

提前停止时，`ACTION_CANCEL_DIAGNOSTIC` 会记录取消原因、当时输入和玩家位置的三维差值，通用 Cancel 表示现场按键记录。

动作加载失败、轨道未匹配及取消原因仍会记录在 `BepInEx/LogOutput.log`。反馈穿模问题时，请附动作名、播放时间点和场景。

### 什么时候需要 JSON

`action.json` 是可选配置文件，用于自定义名称、文件名和播放参数。

默认文件名可直接导入。需要调整时，在动作文件夹添加 `action.json`，只写要改变的字段，其余沿用默认值。

可以用记事本编辑并直接复制下方示例。保存时使用文件名 `action.json`；如果显示为 `action.json.txt`，请去掉最后的 .txt。JSON 只填写配置内容，注释放在文件外。

#### 音乐晚 1 秒开始

```json
{
  "audioDelaySeconds": 1
}
```

#### 单独降低这个动作的音乐音量

```json
{
  "volume": 0.7
}
```

默认是 1，0 为静音；同时受设置页的动作音乐音量影响。

#### 不想重命名下载的文件

```json
{
  "vmdFile": "动作.vmd",
  "audioFile": "音乐.wav",
  "faceVmdFile": "表情.vmd",
  "lipVmdFile": "口型.vmd",
  "cameraVmdFile": "镜头.vmd",
  "lyricsFile": "歌词.lrc"
}
```

资源与 action.json 放在同一目录，只填写实际使用的文件。省略可选文件字段时查找上表中的默认文件名，填 `""` 则禁用该附加文件；禁用表情或口型文件后，该层不再覆盖前一层。

新版仍支持旧的 `"camera": { "vmdFile": "镜头.vmd" }` 写法，无须修改已有 JSON。同时填写时以顶层 `cameraVmdFile` 为准，日志记录 `MMD_CAMERA_FILE_OVERRIDE`；`camera.enabled: false` 仍可关闭镜头。

#### 使用其他文件名的 MP3

BGM.mp3 会自动识别；音乐使用其他名字时，填写这一项即可：

```json
{ "audioFile": "音乐.mp3" }
```

路径相对于 action.json 所在目录。显式指定的 MP3 优先于 BGM.wav，指定文件缺失时会报告错误。

#### 改显示名称，同时微调镜头高度

```json
{
  "displayName": "我的舞蹈特别版",
  "camera": {
    "heightOffset": 0.1
  }
}
```

镜头仍会自动使用 camera.vmd。高度偏移默认是 0，正数抬高、负数降低。

#### 文件存在，但不使用音乐和配套镜头

```json
{
  "audioFile": "",
  "camera": {
    "enabled": false
  }
}
```

不同示例可以合并到同一个 JSON 中。每个动作只放一份 action.json，修改后重启游戏。

### JSON 参数一览

所有字段都有默认值，按需填写即可。文件名和文字使用英文双引号，数字直接填写，开关使用 `true`（开启）或 `false`（关闭）。`null` 和拼错的参数名会在 BepInEx 日志中报错。

#### 名称和文件

| 参数 | 默认值 | 用途与示例 |
| --- | --- | --- |
| `id` | 文件夹名 | 动作的固定标识，不能与其他动作重复或包含英文逗号。例如 `"id": "mydance"`。通常不需要填写；修改它不会改变默认显示名称。改文件夹名会改变默认标识，需要固定时再填写此项。 |
| `displayName` | 文件夹名 | 环状列表显示的名称，例如 `"displayName": "我的舞蹈"`。 |
| `description` | 空 | 动作备注文字，不影响播放；目前不会在游戏中显示说明。 |
| `vmdFile` | `motion.vmd` | 动作文件，例如 `"vmdFile": "动作.vmd"`。此文件必须存在。 |
| `audioFile` | 存在时使用 `BGM.wav`，否则使用 `BGM.mp3` | WAV 或 MP3 音乐文件，例如 `"audioFile": "音乐.mp3"`。填写空字符串 `""` 可禁用音乐；省略则按上述顺序查找，指定缺失文件时不会回退。 |
| `faceVmdFile` | 存在时使用 `face.vmd` | 独立表情 VMD，例如 `"faceVmdFile": "表情.vmd"`。支持纯表情文件，覆盖主动作中的同名表情通道；空字符串禁用该层。文件缺失、损坏或无表情轨道时警告并保留主动作表情，仍可使用有效的独立口型。 |
| `lipVmdFile` | 存在时使用 `lip.vmd` | 独立口型 VMD，例如 `"lipVmdFile": "口型.vmd"`。仅应用已支持的嘴部通道，最后覆盖主动作和附加表情中的同名通道；空字符串禁用该层。文件出错或无可用嘴部轨道时警告并保留前一层结果。 |
| `cameraVmdFile` | 存在时使用 `camera.vmd` | 配套镜头 VMD，例如 `"cameraVmdFile": "镜头.vmd"`。空字符串禁用配套镜头；文件出错时警告并跳过镜头，动作和音乐继续。优先于旧的 `camera.vmdFile`。 |
| `lyricsFile` | 存在时使用 `lyrics.lrc` | UTF-8 歌词，例如 `"lyricsFile": "歌词.lrc"`。空字符串禁用歌词；仅随配乐加载。文件出错时警告并跳过歌词。 |
| `referencePose` | `"A"` | 游戏生成骨架的参考姿势；`"A"` 采用约 30° 上臂下垂校准，`"T"` 沿用原游戏绑定参考。字段和值不区分大小写，只接受 A/T 字符串。参考姿势只影响虚拟骨架，不修改游戏角色的网格绑定数据。 |

资源路径相对于 action.json 所在文件夹，可用 `"音乐/BGM.wav"` 这样的子目录路径；范围限于当前动作文件夹及其子目录。

#### 播放、音量和动作范围

| 参数 | 默认值 | 用途与填写条件 |
| --- | --- | --- |
| `audioDelaySeconds` | `0` | 音乐比动作晚多少秒开始。只能填写大于或等于 0 的数字，例如 `1.5`。 |
| `volume` | `1` | 这个动作的音乐音量倍率，范围 `0`～`1`。还会受到设置页音量影响。 |
| `loop` | `false` | 是否循环角色动作。当前只支持静音动作循环；使用 `true` 时需要关闭音乐。 |
| `requiresHands` | `true` | 是否要求双手可用。手铐等状态会限制需要双手的动作。只有 `bodyMask` 为 `"LowerBody"` 且 `writeFaceMorphs` 为 `false` 时，才可填写 `false`；其他游戏限制仍然生效。 |
| `requiresStanding` | `true` | 是否要求角色站立。填写 `false` 只取消这项要求，其他游戏状态仍可能限制播放。 |
| `bodyMask` | `"FullBody"` | 动作控制范围：`"FullBody"` 为全身；`"UpperBody"` 为上半身，不包括髋部；`"LowerBody"` 只控制腿部。 |
| `writeHipTranslation` | `true` | 是否使用动作位移：水平走位交给原角色控制器，上下起伏应用于髋部。只有动作范围包含髋部时有效；false 关闭两者。 |
| `keepGameExpressions` | `true` | 是否保留原游戏表情叠加；false 优先于游戏内开关。 |
| `writeFaceMorphs` | `true` | 是否使用 VMD 中已支持的表情，如眨眼和嘴型。并非所有 MMD 表情都有对应效果。 |
| `followFaceCamera` | `true` | 是否让游戏原有的面部摄像机跟随这个动作。仍受设置页开关控制，与配套主镜头的开关分开。 |
| `showInRing` | `true` | 是否出现在环状列表。设为 `false` 后无法从列表选中，通常保持默认即可。 |
| `bonePaths` | `[]` | 高级选项：仅控制指定骨骼。留空时由播放器按 bodyMask 和动作轨道选择骨骼。填写公共角色预设中的游戏骨骼完整路径，不是 MMD 的骨骼名；路径须位于所选动作范围内且不能重复，选中的骨骼必须实际存在。 |

只循环腿部动作、不使用音乐和表情的例子：

```json
{
  "audioFile": "",
  "loop": true,
  "bodyMask": "LowerBody",
  "requiresHands": false,
  "writeFaceMorphs": false
}
```

只使用头部骨骼动作的高级例子：

```json
{
  "bodyMask": "UpperBody",
  "writeFaceMorphs": false,
  "bonePaths": [
    "Armature/Hips/Spine/Chest/Neck/Head"
  ]
}
```

#### 镜头参数

镜头参数统一放在 `"camera": { ... }` 对象中，按需修改其中的字段，其余使用默认值。

| 参数 | 默认值 | 用途与示例 |
| --- | --- | --- |
| `camera.vmdFile` | 存在时使用 `camera.vmd` | 保留的旧版镜头文件字段，写在 `camera` 对象中；建议新配置使用顶层 `cameraVmdFile`。同时填写时顶层字段优先。 |
| `camera.enabled` | `true` | 是否使用这个动作的配套镜头。设置页的 MMD 镜头总开关也需要开启。 |
| `camera.timeOffsetSeconds` | `0` | 镜头相对于动作的时间偏移。正数让镜头晚开始，负数从镜头较后的位置开始；与音乐延迟独立。 |
| `camera.scale` | `0.08` | 镜头位置和距离的比例。调整不合适的镜头取景时使用，通常保持默认。必须大于 0，最大为 100。 |
| `camera.heightOffset` | `0` | 整体镜头高度偏移，单位为游戏中的米。正数抬高、负数降低，例如 `0.1`。 |

镜头位置和距离使用固定比例换算，默认每 MMD 单位对应 0.08 个游戏单位。角色身高或腿长变化时，可通过 `camera.scale` 和 `camera.heightOffset` 手动调整取景。

例如，镜头晚半秒开始并抬高一点：

```json
{
  "camera": {
    "timeOffsetSeconds": 0.5,
    "heightOffset": 0.1
  }
}
```

新版继续读取旧 JSON；新增的 `faceVmdFile`、`lipVmdFile`、`cameraVmdFile`、`lyricsFile` 字段供新版使用。schemaVersion、bundle、clipAsset、audioAsset 和 showInTab 属于当前 MMD 配置范围之外的字段，填写后会被校验拒绝。

### 动作事件

动作事件用于定时播放原版音效、脚步或召集 NPC。它们与音乐延迟、镜头参数一样按需配置，省略时使用原有播放方式。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `events` | `[]` | 指定时间点执行的事件。每条填写 time、event，可选 args、repeat。 |
| `onStart` | `[]` | 动作实际开始时执行。每条填写 event，可选 args。 |
| `onFinish` | `[]` | 动作和音乐全部正常结束时执行。 |
| `onCancel` | `[]` | 已开始的动作中断时执行。临时请求仍会自动清理。 |
| `useClipEvents` | `true` | 仅用于 Unity 动画包的内置事件，对 VMD 无影响。 |

例如，仅让这个动作触发围观：

```json
{
  "onStart": [
    { "event": "npc.spectators" }
  ]
}
```

需要安装 NPC 围观插件并开启其总开关；动作停止会自动释放这次请求。完整事件参数、音效与脚步示例见旁边的 [动作事件说明.zh-CN.md](../shared/动作事件说明.zh-CN.md)。

### 参考姿势与接地

motion.vmd 是唯一必需文件，其余按需添加。省略音乐时静音，省略配套镜头时使用游戏镜头。虚拟 MMD 骨架由游戏角色的网格绑定姿势生成，`referencePose` 决定采用 A/T 参考姿势。

默认从游戏角色生成 A-pose 骨架，沿用游戏骨长与体型。骨架由插件生成，动作使用 T-pose 参考时可单独设置：

```json
{
  "referencePose": "T"
}
```

填写 `"A"` 或省略该字段可使用默认参考，修改后重启游戏。这套 A-pose 是通用参考，可能与动作作者模型的姿势和比例有差异；合掌、摸脸、牵手、跪姿等接触位置仍可能有偏差，插件不做自动接触适配。

动作走位默认保留，水平位移经过游戏角色控制器处理碰撞，受阻或取消后停在实际到达的位置。上下起伏以参考姿势为基准，保留首帧的下蹲或抬起，因此脚部可随动作离地。配套镜头与角色走位分别按原始轨迹运行。

头发、裙摆等物理由原游戏处理。资源准备、骨架预热和读档或切换场景后的角色重绑由插件自动完成。

### 表情叠加

默认在原游戏表情上叠加动作表情，保留捏脸形状；关闭 **设置 → 更多动作 → 叠加原游戏表情** 后，仅显示动作表情。动作停止后恢复原版表情控制。

每个动作可强制关闭叠加：

```json
{
  "keepGameExpressions": false
}
```

此时界面开关不能覆盖；省略或为 `true` 时遵循界面设置。`writeFaceMorphs: false` 表示动作完全不接管表情。

支持基础模型的微笑、眉毛、单眼眨眼和元音口型等标准通道，使用 VMD 中实际存在且已映射的轨道。音乐只负责播放，口型来自 VMD 数据。通道映射由基础模型统一提供，动作可直接复用；更换模型后需确认表情布局仍匹配。

### 原版属性与姿势任务

在动作文件夹的 action.json 中按需填写属性，其余资源和播放参数沿用默认值。推荐直接写在根级，也可使用下方说明的 stats 对象。

```json
{ "poseMission": true, "ecstasyPerSecond": 0.1 }
```

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `nativeKind` | "None" | 读取下表中原版代表动作的数值预设；不改变实际动作类型。 |
| `poseMission` | false | 计入原版姿势任务，但仍需满足暴露与任务区域条件。 |
| `stats` | {} | 可选的属性对象形式；直接写在根级的同名字段优先。 |

`nativeKind` 可填值区分大小写：

| 值 | 读取的原版动作 |
| --- | --- |
| None、Interaction | 无额外数值。 |
| Pose | HipShake |
| Onani | OnaniNormal |
| Dildo | UseDildoWallPussy1 |
| DildoFella | UseDildoWallFella1 |
| DildoWait | UseDildoWallWaitPussy |
| SitDildo | SitDildo |
| Sex | SexStandBack |
| Pee | PeeNormal |

预设读取当前游戏主数据中某个代表动作的数值，同类动作之间仍可能有差异。排尿许可、姿势任务、膀胱补充和体力消耗分别由对应字段控制。

推荐把属性直接写在 JSON 根级，也可放入 stats 对象；根级同名字段优先。例如 ecstasyPerSecond=0 会覆盖 stats 内的同名值，关闭本动作的快感贡献。

全部属性字段：

| 参数 | 省略时的默认值 | 含义与限制 |
| --- | --- | --- |
| `ecstasyPerSecond` | 预设 AddEcstasy；None 为 0 | 基础快感增长/秒。**快感满值为 1（100%），0.1 表示基础每秒增加 10%**。继续使用原版动作速度、心跳和强化倍率，因此不保证最终每秒恰好增加该数值。原版仍处理道具贡献、自然回落和高潮阈值；0 只关闭本动作贡献，不阻止原版道具效果。 |
| `dokidokiAdd` | 预设 AddDokidoki100 ÷ 100；None 为 0 | 本动作的紧张度贡献，范围 0～1，仍受原版等级倍率影响。不是 BPM，也不是每秒累加量。原版每帧重算后叠加一次、限制在 0～1，再平滑心率、呼吸等；自宅保留原版心率规则。 |
| `moisturePerSecond` | 0 | 每秒排入膀胱待吸收队列的量，采用 0～1 的归一化单位。实际吸收速度由原版限制，当前主数据约 0.01/秒；自动补充技能会按原版规则覆盖队列。停止动作后，已排入的部分仍继续吸收。不是衣物湿度。 |
| `staminaPerSecond` | 0 | 每秒消耗的原生体力单位，不是百分比。使用原版消耗方法，保留恢复冷却和耗尽闪烁；耗尽时停止自定义动作。 |
| `strange` | 预设 Strange；None 为 0 | 原版暴露计算之后的动作可疑度基础值，之后继续乘原版光照、察觉度和视线系数。不会直接增加全部 NPC 的可疑条。 |
| `strangenessScale` | 预设 StrangenessScale；None 为 1 | 对原版计算出的方向性暴露可疑度乘此倍率，再加 strange。0 可关闭该部分视觉暴露贡献，不会关闭原版听觉等独立渠道。 |
| `discomfort` | 预设 Discomfort；None 为 0 | 动作提供的不适上限基础值，与原版服装、方向和状态的值取较大者，再沿用原版视线规则；不按帧持续加到缓存。 |
| `canStartPee` | false | 有膀胱存量时允许动作调用原版排尿流程，沿用计时、粒子、排出速度和结束处理。不是强制填满膀胱；false 也不会阻止原版满值后的自然排尿。 |

属性未填写且未使用 nativeKind 预设时，各项额外数值默认为 0，可疑度倍率为 1，排尿和姿势任务开关为 false。按需填写字段即可，displayName 可省略。

数值填写有限的非负数字，dokidokiAdd 范围为 0～1。属性可写在根级或 stats 对象中；数值字段中的字符串、null，以及 stats 内未知或重复的字段会被校验拒绝。

快感满值是 1（100%）；ecstasyPerSecond=0.1 表示基础每秒增加 10%，实际受原版动作速度、心跳和强化倍率影响。dokidokiAdd 是紧张度贡献，不是每秒增长量。

达到原版高潮条件时，MMD 停止，由原版接续高潮动画和结束流程；独立动作的专属高潮片段暂未接入。排尿要求膀胱有存量，并遵循禁止排尿和液体显示设置，已启动的排尿由原版计时结束。体力耗尽也会停止播放。

属性贡献从动作实际开始后生效，暂停时暂停，停止、切换或读档后结束。加载等待和预览阶段沿用原版属性计算，已排入膀胱的待吸收量仍由原版吸收。每次开始记录一条 ACTION_STATS，列出实际解析数值。

### 常见问题

- **列表里没有动作：** 检查 `motion.vmd` 的名字、文件夹和 JSON 格式；等待准备完成后重新打开转盘，修改文件后重启游戏。
- **指定了文件却未加载：** 检查相对于 `action.json` 的路径。显式指定的文件不存在时不会改用默认文件；附加表情或口型会保留前一层结果，镜头和歌词会跳过，错误原因见日志。`vmdFile` 不能留空。
- **没有音乐：** 检查 `BGM.wav`、`BGM.mp3` 或 `audioFile` 指定的文件，以及游戏和插件音量。
- 歌词未显示时，确认 `lyricsFile` 指定的文件或默认 `lyrics.lrc` 使用 UTF-8 编码，歌词行带有时间标签，且动作正在播放配乐。修改文件后重启游戏。
- **没有配套镜头：** 检查 `camera.vmd`，并开启设置页的 MMD 配套镜头。
- **表情仍然叠加或完全不动：** 检查 `keepGameExpressions`、`writeFaceMorphs` 和 VMD 中是否存在支持的表情轨道。
- **没有操作却提前退出：** 在商场某些位置播放部分动作可能提前退出，属于已知问题。
- **坐下、手脚触地时穿模或脚部翻转：** 这些姿势仍有适配偏差。角色整体走位保留碰撞，不代表手、脚和腿会避开场景地面或墙面；当前没有肢体避障或强制贴地。遇到问题时请记录动作名、时间点和场景，目标到位或骨骼映射一致也不能证明整条肢体姿势正确。

反馈问题时请附 `BepInEx/LogOutput.log`、动作名和大致时间点。

### 升级兼容

- 独立表情、口型和新增顶层文件字段从 MMD 1.4.0 开始支持；该版本继续读取旧 JSON，旧版插件不支持新增字段。
- 从 Seleka2 前缀版本升级时，请运行安装脚本迁移动作与配置。安装器会备份移走旧 DLL，保留已有 SFM 配置；手动升级需先移走旧 DLL，避免重复加载。
- 更新时请同时安装配套的更多动作与 MMD DLL。
- 使用过配套 PMD 模型配置的动作，请删除 `action.json` 中的 `modelFile`。`source.pmd` 不参与导入；已有模型文件无需用于本插件。
