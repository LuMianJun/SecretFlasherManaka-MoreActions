# 游戏骨架接入回归

在仓库根目录运行：

```powershell
dotnet run --project mmd/CompatibilityValidation/CompatibilityValidation.csproj
```

命令输出本次通过的断言数量；失败时输出具体断言并返回非零退出码。真实动作回归可加 `-- --motions <六动作目录>`。

2026-11-15默认回归通过12,991项；加上原始六动作后通过24,108项，覆盖六文件SHA256、A/T参考和2,674个时间样点。Shake整段、腰振り最后15秒、盛装登场60–90秒按10Hz加密采样。每组核对80骨有限值、重复无累积、停止恢复、角色根所有权，以及非中性扩展相对剥离扩展版本的实际输出差异。测试要求六动作目录的上级含`motion-sources.json`，文件按`<动作名>/motion.vmd`读取；原始动作不随仓库分发。

工程直接链接生产解析器、上游求解器、骨架快照、采样树、缓存、表情与身体姿势租约，覆盖：

- A/T 参考、正负 90° 原生 Armature、不同骨轴、身高及大小腿比例包装，逐骨比较世界位置和旋转。
- 真实腿脚 bind P/Q、隐藏控制父空间归一化、51 个 Humanoid 的测量几何，以及显式关闭 IK 时空动作保持原生世界参考姿态。
- 原 Bundle 全80路径、两套身体网格各78个原始 bind 矩阵；以78个绑定关节和两个单位局部变换中间父构建80个采样节点，逐项验证原生世界参考和 Center 位移。
- 独立复现错误父空间导致的空动作 90° 偏转；验证一个 MMD 位移单位只换算一次，等于 0.08 世界米。
- 非单位 mesh-local TRS、Hips/Spine/腿部反比例包装及 Spine→Chest 长度耦合，以实际 native 关节位置验证几何采样。
- 首帧髋高、绝对水平位移、循环端点、重复采样和角色根节点所有权。
- 31条可选原生骨逐轨写入、双眼／両目、四捩与辅助骨、上半身3、腰／取消与原足部 IK 衔接、肩P/C、D/EX，以及显式拇指0的三节映射。
- 没有拇指0时保留上游1/2编号，拇指0与原生末节轨并用时各叠加一次；可选父骨未选中时只保留源轨坐标换算，不写其原生姿势。
- 未知轨隔离、遮罩、反复采样／跳转无累积、停止恢复，以及可选骨原生父旋转和尺寸保留。
- 真实 VMD 文件中的 `Foot_L` 别名、NUL 后尾部内容、后续有效帧，以及标准足踝轨道优先于原生别名。
- 原生膝修正作用域、停止恢复、上下身遮罩和附属物体边界。
- 热缓存复用、并发独立采样树、体型通知及播放中形状替换。
- 构造失败后销毁采样树、归还原生状态，以及重新准备和播放恢复。

一般动作的转移一致性仍以同尺寸、同骨轴上游实例核对；这种比较不能单独证明输入空间正确。新增空动作、测量几何和位移单位检查直接从原生世界参考及数值契约推导答案。默认足 IK 即使没有轨道也可能改变腿部姿态，测试会记录该变化；只有显式关闭 IK 的零动作才对全部 51 个 Humanoid 断言姿态不变。循环末端另用普通求值的左极限核对，固定版本原始播放器与移植核心的一致性由相邻的 `UpstreamValidation` 工程检查。

Unity 变换、数学、网格元数据和日志使用离线替身，不运行游戏渲染、蒙皮、原生回调或场景碰撞。完整 Bundle 夹具的来源、哈希及复算方法见 [Fixtures/README.md](Fixtures/README.md)。80条路径按源轨与遮罩接管，没有对应轨道的可选骨保留原生 localTRS。该回归不证明全部原生体型参数已接入，已覆盖的几何包括颈长、肩宽和腿间距，范围以各项回归断言为准。

真实动作的60次非单调跳转均观察到原始核心已有的Head及后代历史依赖，完整扩展版与剥离版都出现；最大观测约21.04°、4.47cm。逐点重复和跳转后的再次重复保持稳定。这些记录以`REAL_MOTION_CORE_SEEK_HISTORY`单列，不能把本回归通过解释为任意跳转均能还原相同姿态；本次未修改上游核心的时序策略。
