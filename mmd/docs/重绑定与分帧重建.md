# 重绑定与分帧准备

MMD 1.4.12 使用原生骨轴采样树、固定上游求解及附加轨道适配。文件读取与 Unity 对象准备分开处理。

- 主线程按公共 JSON 路径采集当前角色引用、绑定矩阵、Armature 变换、根尺度和已支持的长度包装。不会遍历服装骨骼来扩大身体预设，也不向本地写回快照。
- 原生 ReAdjust／OnChangeBody 请求重新核对。等待原生缩放回调后比较实际几何；纯世界位移、朝向和没有几何变化的通知不会重建。真实体型变化会使旧的活动采样树失效，停止旧姿势写回并归还原生控制。
- 快照与采样节点创建按可暂停步骤推进；主线程每帧最多推进8步，以2ms为调度预算。单次 Unity API 无法被抢占，因此不是单个 API 的硬性耗时保证。
- 数据读取在后台进行；原生骨轴树和上游 Transform 求解在主线程执行。旧的后台合成 MMD 拓扑已移除。
- 相同形状按 A／T 模式重绑并复用采样树；每种模式最多保留两种闲置旧形状。单次播放独占上游游标、开关和辅助节点，并发租用使用独立树。
- 80条路径中的78个关节使用网格 bind，两个无 bind 的 BreastRotate 中间父使用已核对的原始单位局部变换；绑定路径和 bind 集合均进入缓存匹配。隐藏控制容器使用单位 TRS，逐骨原生世界参考与已换算尺寸保留。附加轨道查找与映射在创建播放时完成，不逐帧发现骨骼或读取 JSON。
- 游戏播放由 IPreparedActionSource 门控，等待准备完成后才播放；直接 API 和离线调用保留同步准备入口。

`MMD_RIG_READY mode=rebind` 表示重绑复用，`mode=build` 表示新建。缓存、并发及体型失效由 CompatibilityValidation 验证；原游戏加载耗时需实机测量。
