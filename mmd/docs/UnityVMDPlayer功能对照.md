# UnityVMDPlayer 功能对照

本文对应 MMD 插件 1.5.1。标准身体解算源自 [hobosore/UnityVMDPlayer `2cee8abd56c68ad3e88bcf4086e33185aa5ca4e8`](https://github.com/hobosore/UnityVMDPlayer/tree/2cee8abd56c68ad3e88bcf4086e33185aa5ca4e8) 的 Player、Reader 和 QuaternionExtensions，固定来源与文件校验记录见 `Plugin/Upstream/upstream-source.json`。

未注入游戏控制层的路径与固定上游进行同输入差分。实际游戏路径使用独立的中心、槽、腰及上下半身，补充足部朝向换算、显式零位移关键帧和跨帧 IK 开关。隐藏参考骨架、原生姿势租约、表情、音乐、镜头及走位由游戏适配层负责。

`MmdAdditionalTracks` 在足部解算前后按轨道语义处理扩展。相对原版的差异由离线报告记录，扩展控制的预期输出与游戏所有权由兼容回归核对。

## 按执行顺序对照

| 环节 | 固定上游的处理 | 当前游戏接入 |
| --- | --- | --- |
| 骨架入口 | 通过 Humanoid API 取骨，按 Avatar 的 skeleton 恢复初始局部位置和旋转。 | `MmdTargetSnapshot` 从固定身体网格的 bind pose 读取中立数据；`RuntimeVmdRig` 以单位 proxy/Armature 控制空间构建隐藏树，保留子骨的米制世界点位及原生骨轴，`UpstreamAvatar` 提供所需 Humanoid 接口和初始姿势。 |
| 路径与标准映射 | Player 将 Humanoid 骨绑定到固定 MMD 名称。 | `body-bones.json` 保存80条固定路径；`GameHumanoidMap` 将原生路径映射到 Humanoid，标准求解采用上游映射。Chest 对应上半身2、Foot 对应足首；上半身3与 D/EX 由有轨时启用的附加层处理。 |
| 当前体型 | 使用初始化后的角色几何和两段腿长。 | 快照计入实际根尺度、大腿／小腿及 Spine 到 Chest 长度因子，识别原生倒数缩放包装节点。颈长、肩宽和腿间距按固定 bind 轴重建米制偏移并计入形状签名；不读取动画后的骨位置作为参考。 |
| A/T 参考 | 从 Avatar 描述姿势恢复参考，Play 额外将左右上臂绕角色 forward 镜像转动30°。 | 默认 A；`referencePose: "T"` 保留游戏绑定参考。调整在隐藏树完成，使用同一原生骨轴，不追加旧 neutral 校准。离线 T 对照仅跳过原版已有条件中的 A 手臂旋转。 |
| 文件输入 | Reader 按原始骨名建立轨道，并筛选位置／旋转 key。 | 公共解析器只读一次文件。兼容层处理 NUL 尾部填充及常用拼写，保留坐标换算后的原始数值、重复 key 和 IK 记录顺序。 |
| 坐标与单位 | 位置和四元数的 x/z 取负；位移系数为 `0.08f`。 | 方向只转换一次，原四元数不预先归一化；隐藏树具有角色实际米制尺寸，不按旧合成骨长比例二次缩放。镜头另有比例设置。 |
| 关键帧插值 | 位置分轴贝塞尔、旋转 Slerp；位置 key 筛选会丢弃显式零值。 | 保持上游的分轴贝塞尔与旋转插值。游戏路径保留足 IK 显式零位置，并能从首个有效帧查到正确区间。 |
| 旋转组合 | `PlusRotation`／`MinusRotation` 对欧拉角加减，再生成四元数。 | 使用相同组合方式，不替换成另一套四元数附加规则。 |
| 连续时间 | 对整数帧 n、n+1 求解后插值，部分控制读取外层 n，结果受此前状态影响。 | 沿用两端点及 Quaternion.Lerp 采样。游戏路径每次按目标时间读取足和脚尖的 IK 开关。 |
| 播放时钟与时长 | 按 `FPS * Time.deltaTime` 推进，在 Reader 末帧结束或循环。 | 公共 DSP 时钟统一动作、音乐、事件和镜头，按30帧/秒请求姿势；标准求解保留到达支持末帧时停止继续求解的 guard。附加轨道可延长有效范围，音乐仍按配置延迟和自身时长结束。 |
| 暂停与 API | 提供 Play、Stop、Pause、JumpToFrame、SetFPS 及开始／结束回调。 | 游戏暂停冻结公共时钟、暂停／重排音乐并停止事件和位移。对外使用 `ActionPlaybackApi.Request/Stop`、播放状态和通知；MMD 另有 `MotionPlaybackApi`，不提供同形组件 API。 |
| 身体调用顺序 | 全亲、上身、下身、Center/Complement、Ghost、腿 IK、脚尖 IK，部分阶段重复执行 exact 与 interpolate。 | 游戏路径在 Ghost 写回前求独立控制层级。腰／取消、肩 P/C、上半身3及拇指转换在 IK 前处理，D/EX 与捩转在 IK 后处理。 |
| 腿 IK | 由髋、膝、踝几何及参考轴计算髋膝角度，沿参考换算的单轴弯膝。 | 保留上游两段公式和膝轴。初始腿形补偿随当前全亲旋转换算，并保留原有目标残差。 |
| 脚踝与脚尖 IK | 足 IK 定脚踝位置，脚尖位置先调整脚掌。足 IK 启用时，最后按足 IK 的旋转重新对齐脚掌。 | 足 IK 父有有效轨道时沿用目标树。父轨道静止或缺失时，如果双链开启、脚尖有有效位移、足 IK 旋转全程中立，也让脚掌对准脚尖位置目标。其余输入沿用原游戏适配路径。缺少原生 Toe 时跳过该侧 ToeIK。 |
| IK 开关 | 当前整数帧命中记录时更新，之后保留状态。 | 游戏路径按各侧、各链读取当前帧或之前最近的记录，无记录时默认开启。足与脚尖均关闭时保留 FK 踝姿态。 |
| 下半身补偿 | Complement 按原关键帧分支与欧拉加减处理上下半身位移和旋转。 | 游戏路径把上半身、下半身分别挂在腰支点下，两侧大腿经过各自的腰取消节点。 |
| Ghost 到原生骨轴 | 换算为 `inverse(父worldQ) * GhostWorldQ * inverse(Ghost初始worldQ) * 骨初始worldQ`。 | 沿用骨轴变换公式，按父先子后写回；游戏侧再施加角色当前朝向。 |
| 输出到游戏 | 直接写 Humanoid 骨的局部或世界姿势。 | 恢复本帧原生基线后写回受控骨。水平髋位移交给控制器，竖直髋位移相对 Avatar 根写回。 |
| 循环位移末端 | Update 到达最后支持帧即结束／循环。 | 从最后可播放帧已计算的 n+1 端点提取周期位移，不放宽标准终帧 guard；之后 Reset 恢复初始化树、游标与开关状态。 |
| 原生动画与停止 | 播放时关闭 Animator，停止时重新开启。 | 保留游戏 Animator、体型和状态逻辑；`ActionBodyPoseLease` 撤回旧输出、采集原生基线并隔离膝／趾修正。停止归还本次受控骨，附属物理由游戏处理。 |
| 表情与口型 | MorphPlayer 按模型形态键名称绑定。 | 使用固定身体网格的表情映射、捏脸保护和原生表情叠加。主动作→附加表情→附加口型按顺序覆盖同名完整轨道，口型层只处理口部。 |

## 支持范围

标准身体轨道包括全亲、中心、槽、上下半身、头颈、肩臂、手腕、上游指骨、腿膝踝及左右足／脚尖 IK。原生标准骨别名按 Humanoid 映射绑定，例如 `Foot_L` 对应左足首。

### Rabbit Hole 开场脚掌朝向（2026-11-17）

原动作首帧开启左右足和脚尖 IK。双足 IK 各有 4,802 个单位旋转关键帧，开场脚尖位置目标在脚踝后方。v1.7.8 把脚尖目标挂在足 IK 目标下，先定脚踝位置，再旋转脚踝去够脚尖目标。固定上游 `2cee8abd` 会在脚尖调整之后用足 IK 旋转再次对齐脚掌。用游戏参考骨架代入首帧，两种方法给出的目标方向相差约左 129°、右 133°。这是目标向量的离线计算。 [旧版目标树](https://github.com/LuMianJun/SecretFlasherManaka-MoreActions/blob/v1.7.8/mmd/Plugin/Rig/GameMmdSkeleton.cs#L130-L150) · [固定上游脚尖求解](../UpstreamValidation/reference/UnityVMDPlayer.cs#L1232)

用户反馈旧版开场正常，v1.8.1 的 FK 对照仍有异常。这里用 v1.7.8 的源码核对旧求解器。关掉 IK 会同时失去脚踝和脚尖位置约束。修正候选沿用已解算的脚踝位置，由脚尖目标决定朝向。按整条轨道判断是否采用这条路径，单帧的零位移仍是有效关键帧。用户用已安装的候选播放原版 Rabbit Hole，确认开场正常。

上游公开 [#3](https://github.com/hobosore/UnityVMDPlayer/issues/3) 报告腿不动和空引用，报告人关闭后未留修复说明。查过仓库公开的开放和已关闭条目，未发现描述本次脚尖方向覆盖的报告。 [公开条目](https://api.github.com/repos/hobosore/UnityVMDPlayer/issues?state=all&per_page=100)

### 「足部异常」的足 IK 旋转基准（2026-11-17）

这个动作从第 0 帧起启用双足 IK，关闭双脚尖 IK。每侧有 4,168 帧。用中心、大腿、膝盖、脚踝组成 FK 旋转，再与对应的足 IK 四元数比较，得到近似固定的绕 X 轴偏差，左侧 117.6054°，右侧 117.6217°。用户确认 FK 对照正常，但安装 Rabbit Hole 候选后原动作仍有异常，因为它没有启用脚尖 IK。

本机另存的「足部异常（IK基准修正）」保留足 IK 开关和位置关键帧，用每侧相对旋转的中位数校正 8,336 个足 IK 四元数。校正是右乘固定基准的逆，动作里的逐帧旋转差异仍然保留。字节对照确认其余数据相同。与 FK 旋转相比，校正后第 95 百分位角差约左 0.187°、右 0.068°，左侧第 638 帧仍有约 38.87° 的差异。对照版的锁脚效果和残余差异待实机核对。

输入兼容层接受既有拼写，如 `上半身２` 和 `左足IK`。应分别比较原文件直接交给上游，以及兼容后交给上游的结果；名称兼容不能被算作求解算法差异。

80条共享路径是可绑定范围，51个标准 Humanoid 输出不是支持上限。附加层按实际轨道支持独立眼／両目、四条腕／手捩及原生扭转辅助骨、腰／取消、肩 P/C、上半身3、足／膝／踝 D、足先 EX 和唯一匹配的清单原生骨。显式親指０启用该侧三节0/1/2映射；没有该轨道时保留上游指骨映射。

附加写回受动作范围和 `bonePaths` 遮罩约束。可选原生骨在原生基线上叠加增量并保留尺寸，停止归还本次所有者；作者模型没有对应目标的裙发、道具和中间骨不能仅凭近似名字绑定。眼 morph 由表情层处理。

`body-bones.json` 的 Source/Fallback 字段保留共享格式；标准映射由上游 Humanoid 字典决定。附加层可利用清单来源和原生名称匹配辅助轨，路径清单、标准输出与某支动作实际启用的轨道是不同范围。

固定上游公开 `LeftUpperArmTwist`／`RightUpperArmTwist`，但该提交的注册条件、Ghost 和最终保存链未构成完整可用的捩骨输出。本地腕／手捩与辅助骨支持属于附加功能；51个绑定也不代表上游 Reader 支持的全部名称。

## 游戏兼容与已知缺口

- 采样树按布局、bind 数据、尺度、已纳入的体型参数及 A/T 参考缓存。位置或朝向变化可复用；形状变化重新准备，旧播放失效后交还原生控制。
- 颈长、肩宽和腿间距进入参考几何及形状签名，不构成所有原生体型参数或任意骨架改造的完整认证。
- `UpstreamAvatar` 的描述姿势来自网格 bind，未直接读取原 Avatar 的 `humanDescription.skeleton`。两者在拇指上有已测差异；游戏适配沿用该来源，同骨架对照向双方提供相同描述姿势。
- 没有 VMD 作者 PMX 的参考骨架、grant、刚体和蒙皮。同骨架下与上游一致，只验证求解移植；不同角色的接触位置仍可能不同，坐下穿地需另做实机验收。上游已有的目标残差继续保留。
- 控制器只处理整体水平移动的场景碰撞。试验性接地可以在带匹配计划的构建中启用，覆盖已判定的支撑手脚；四肢与墙面仍可能相交。
- `SuppressKneeOffset` 没有生产消费者；租约隔离原生修正的 Transform 写入，不改内部高度记账。此前捕获未证明这些数值是 Shake 异常原因。
- 缩放验证覆盖均匀根尺度及原生倒数包装节点，不承诺任意非均匀缩放、剪切或外部骨架改造等价。

## 验证方法

`UpstreamValidation` 编译固定版本未修改的 Player、Reader 和 QuaternionExtensions，先校验源码哈希，再比较未注入游戏控制层的输出。原始输入与兼容输入分别核对；兼容原版独立读取临时二进制，生产执行实际兼容层，确保 addiction 等动作有非空有效轨道。项目已删除旧模式参数和 `UPSTREAM_VALIDATION` 编译符号。

标准核心六动作、A／T、三种缩放共36组合、380,970次采样，比较80根骨骼的局部／世界位置与旋转，最大差均为0。64组合的合成对照覆盖全亲、大角度控制组合、下半身、头颈、零／重复／稀疏 key、IK开关及前后查询历史；合成加真实原始／兼容输入的门禁通过398,481项检查。

`PlaybackParityValidation` 在去除或恢复附加轨道后测量游戏写回相对原版的差异。下述误差来自 1.4.14 的旧试验基线，六动作 A／T 共 12 组合，最大位置差约 0.002331 mm，旋转差约 0.00004608°。1.5.0 的游戏路径有显式控制和关键帧差异。仅还原控制器水平位移和固定首帧起点，没有逐帧或逐骨校准。随后恢复附加轨道，仍与同一原版基准比较并列出各骨变化，结合扩展契约判定；附加层非零输出不能自动解释为正确。

分组恢复测量完成50个有效组合。腰振182.8秒的脚踝大差来自腰／取消组，盛装71.2秒的脚趾约70.46 mm变化来自D/EX组；Shake附加组没有使腿足超出标准门限。用户已先安装隔离构建的无附加层1.4.14测试版，以实机验证标准基线；该测试版没有改变正式源码的完整扩展支持。无附加层测试版关闭的是身体骨轨道扩展，附加表情／口型继续保留。

`CompatibilityValidation` 检查原生参考几何、世界米单位、体型与缓存失效、原生姿势所有权、停止恢复及附加轨道契约。Reset／循环等包装生命周期单独核对；原版访问历史不再由任意 seek 确定性断言覆盖。

```powershell
dotnet run --project mmd/UpstreamValidation/UpstreamValidation.csproj

dotnet run --project mmd/CompatibilityValidation/CompatibilityValidation.csproj

dotnet run --project mmd/PlaybackParityValidation -c Release -- baseline "动作目录" "输出目录/playback-baseline.json"

dotnet run --project mmd/PlaybackParityValidation -c Release -- extended "动作目录" "输出目录/playback-extended.json"
```

以上验证使用离线数学与场景边界，不证明原作者 PMX、蒙皮接触或游戏画面等价。1.4.13曾用旧模式完成246,553项来源对照，并用另写算法降低目标残差；这些历史数字不能证明当时生产输出与上游一致。替代算法及其验收目标已由本轮直接差分取代。

## 求解边界

标准求解以固定上游源码为行为基准。必要游戏适配负责相同参考几何、输入和控制权接入，是否保持输出由完整差分验证；附加轨道的预期变化逐项说明。后续若修改标准求解，应先明确改变的上游行为和差分结果，不能将通用算法重写统称为兼容适配。VMD 不包含源 PMX 的参考骨架、grant、刚体和蒙皮；MMD 刚体、材质／UV Morph 仍不在支持范围。试验性接地仅处理带计划的手脚支撑。
